# Участие в разработке

Проект находится на этапе спецификации. Сначала прочитайте
[текущий статус](README.md), [документацию](docs/README.md) и
[общий план](https://github.com/vovkins/ru-llm-scanner/issues/1).

## Рабочий процесс

Каждый этап имеет отдельную GitHub Issue с подробным планом и чекбоксами.
До реализации план показывается владельцу проекта в чате и получает явное
согласование. Для изменения границ или семантики согласование обновляется.
Исправления в пределах уже согласованного этапа не требуют повторного запроса.

Изменение должно объяснять проблему, итоговое поведение, проверки и ограничения.
Свяжите его с задачей этапа и обновите документацию в том же изменении.
Не закрывайте чекбокс только потому, что код написан: проверьте результат.
Не начинайте следующий этап автоматически после завершения предыдущего.

## Окружение и проверки

Инструкции установки инструментов и фактически доступная команда проверки
находятся в [руководстве разработчика](docs/development.md). На этапе 1
проверяются JSON Schema, синтетические примеры и ссылки; runtime-тестов
сканера пока нет. Не выдавайте контрактную проверку за проверку детекторов.

Меняя контракт, синхронно обновите схему, документацию, примеры и проверку
инвариантов. Добавьте проверку существенного нового сценария/регрессии;
не добавляйте тест, который лишь повторяет обратимое оформление документа.
Для изменения архитектуры обновите [ADR](docs/decisions/README.md).

## Данные и upstream

Используйте только синтетические данные и неработающие примеры credentials.
Не коммитьте реальные отчёты scanner, Git-репозитории пользователей, токены,
локальную конфигурацию доступа или веса модели. Как сообщать о проблемах —
в [SECURITY](SECURITY.md).

Изменения механизма обнаружения поступают из закреплённой версии прокси
по [процедуре обновления](docs/architecture.md). Не переносите случайные части
детекторов в обход lock и проверок. Статус лицензирования описан
[отдельно](docs/licensing.md); не приписывайте проекту ещё не выбранную лицензию.
