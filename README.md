# ru-llm-scanner

Локальный сканер чувствительных данных в Git-репозиториях. Проверяет состояние
коммита или переход A → B и сохраняет **HTML и JSON с полными значениями**,
контекстом, категорией, файлом, строками, коммитом, источником и confidence.
Анализ выполняется локальными контейнерами, без интернета и внешних LLM/API.

Распознавание основано на закреплённой версии
[ru-llm-proxy](https://github.com/vovkins/ru-llm-proxy): NER, правила для реквизитов
и credentials, отдельный словарь бизнес-терминов.
[Категории и известное качество](docs/reference/detection.md).

## Первый запуск

Нужны **Python 3.11+** как `python3` с venv/pip, Git, GNU Make и доступ non-root
оператора к **rootful Docker**: Linux AMD64 или ARM64, API 1.49+, Compose v2+,
BuildKit. Сборочный сервер должен иметь доступ к источникам пакетов и модели.
[Подготовка хоста и ресурсы](docs/admin/README.md).

Команды выполняются в доверенном checkout **scanner**, а путь `REPO` указывает
на отдельный, уже склонированный проект:

<!-- walkthrough:quickstart -->
```sh
make build
make test
make scan REPO="$HOME/git/пример project"
```
<!-- /walkthrough:quickstart -->

Замените путь на свой. `build` сам подготовит окружение, модель и оба образа;
`test` проверит комплект; `scan` прочитает состояние **HEAD** и напечатает
абсолютные пути `report.html` и `report.json`. Откройте HTML локально в браузере.
Ручные `deployment.json`, хеши, выбор wheel и запуск сервисов не нужны.
Каталог отчёта создаётся автоматически с приватными правами вне клона.

**Версия интерфейса — v0.3.0.** Для воспроизводимого запуска выбирайте
доверенный Git checkout конкретного релизного тега; [версии и получение](docs/admin/releases.md).
Для прежнего v0.2.0 сохранён [отдельный маршрут](docs/admin/advanced.md).

## Четыре команды

| Задача | Команда из checkout scanner |
| --- | --- |
| Подготовить или обновить локальный комплект | `make build` |
| Выполнить повседневные проверки | `make test` |
| Проверить HEAD либо выбранный коммит | `make scan REPO='/srv/git/example project' COMMIT=HEAD` |
| Проверить переход конечных состояний | `make diff REPO='/srv/git/example project' FROM=COMMIT_A TO=COMMIT_B` |

`make help` показывает справку. [Руководство пользователя](docs/user/README.md)
объясняет конкретный коммит, настройки, strict baseline и чтение отчёта.
[Администратор](docs/admin/README.md) — сборку, обновление и диагностику.
[Справочник параметров](docs/reference/simple-workflow.md) — точные defaults и ограничения.
Для Jenkins вызывайте [прямой CLI](docs/admin/jenkins.md): `./scanner scan|diff`.

## Что означает результат

| Код прямого CLI | Результат |
| --- | --- |
| `0` | Заданная проверка завершена без находок |
| `1` | Проверка завершена, найдены чувствительные данные |
| `2` | Ошибка или неполнота, даже если часть находок сохранена |

**GNU Make возвращает свой код ошибки рецепта** (обычно 2 и при находках).
Для автоматизации точные 0/1/2 даёт `./scanner`. `build` и `test` возвращают
0 при успехе, 2 при отказе; ожидаемая находка внутри synthetic test не ломает suite.

Откройте [синтетический HTML](examples/demo/report.html) и
[его JSON](examples/demo/report.json). Это иллюстрация, **не baseline**.
Отчёты содержат найденные значения полностью, поэтому храните их приватно;
консоль содержит только техническую сводку и пути. HTML самодостаточен, без CDN.

## Охват и ограничения

Scanner читает **tracked Git-объекты коммита**. Staged, untracked и незакоммиченные
файлы не проверяются. Код, hooks и filters входного проекта не исполняются,
checkout/fetch не выполняется.

Snapshot проверяет все поддерживаемые текстовые файлы состояния. Diff проверяет
**полное содержимое изменённых файлов B**, включая неизменённые строки.
Для подтверждения неизменённых файлов нужен совместимый доверенный clean baseline A
и `REQUIRE_BASELINE=1`. Baseline автоматически не выбирается и не продвигается.
[Coverage и assurance](docs/reference/scan-modes.md) задают границы результата.

Промежуточная история A…B не сканируется: добавленный и удалённый между ними секрет
может остаться в Git. Содержимое LFS/подмодулей, PDF/Office/OCR, изображения и
архивы вне обещанного охвата. SVG/XML могут читаться как текст, без визуального анализа.
Исключения, неподдерживаемые файлы и ошибки отражаются в манифесте.
Нулевой результат не гарантирует обнаружение каждого секрета;
[известные FP/FN и измерения](docs/reference/detection.md) опубликованы отдельно.

Текущие исходники закрепляют Analyzer `9e47e65` и принятую политику `logistic`: она
дополнительно находит Base64-подобные контейнеры, в том числе с обычным содержимым.
Это может давать дополнительные кандидаты; оценка и ограничения опубликованы в
справочнике. После смены engine/profile нужен новый полный clean snapshot для baseline.
