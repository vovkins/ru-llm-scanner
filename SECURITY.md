# Безопасность и сообщения о проблемах

Текущая версия — `0.1.0`. Гарантированный срок реакции на сообщения не установлен.
Реальные CLI/Compose/Analyzer проверены на CPU Linux ARM64
в Docker Desktop; Jenkins adapter проверен локально без controller.
[Матрица свидетельств](verification/README.md) отделяет static/schema/unit stub,
real model, independent quality и production behavior. Это внутренние проверки,
не независимая сертификация или гарантия отсутствия дефектов.

Исходные [замечания ревью](docs/review/README.md) и
[исправления RV-01–RV-05](verification/operations-stage-2/README.md) сохранены
отдельно. Hostile Git config/hooks/filters/textconv/replace/grafts, ссылки и
missing objects проверены синтетическими сценариями без исполнения кода/fetch.

## Как сообщить

На 2026-10-18 в репозитории GitHub отключён Private vulnerability reporting.
Приватный адрес для приёма сообщений владельцем пока не объявлен.
Не считайте обычную Issue закрытым каналом.

Для общей проблемы можно создать
[обезличенную Issue](https://github.com/vovkins/ru-llm-scanner/issues/new),
без credentials, персональных данных, внутренних адресов и полного отчёта.
Если детали нельзя публиковать, сначала запросите у владельца закрытый канал,
передав публично только факт необходимости такого канала. Не публикуйте детали
уязвимости или действующие секреты до согласования способа передачи.

Настройки проверены read-only через GitHub API; включение приватного канала
и выбор контакта остаются решением владельца. Проверка секретов GitHub не
заменяет осторожность при публикации и анализ scanner.

## Модель доверия

Проверяемый Git-репозиторий недоверенный: его код, хуки, `.gitattributes`,
конфигурация scanner и HTML-подобные строки не должны выполняться. Читаются
сырые объекты, внешние diff/textconv/filters, `replace`-объекты, lazy fetch и
неявные пользовательские Git-конфигурации не должны менять анализ. Команды
передаются аргументами без shell-интерполяции. Ссылки не разыменовываются.
Изоляция реализована и проверена на этапе 3 через отдельный metadata-view:
исходный config не применяется, refs фиксируются, сырые commit/tree/blob
проверяются по OID. [Точные ограничения](docs/git-reader.md) включают запрет
внешних/shared metadata и symlinks в object store. Входные объекты должны
оставаться неизменными во время чтения; защита от активной параллельной подмены
хостовым процессом не заявлена. Ошибки не содержат stderr или blob целиком.

Образы Analyzer, lock, профиль проверки и baseline доверенные и поступают
из контролируемого процесса. Проверяемый проект не выбирает скрытый allowlist,
не ослабляет scope и не подменяет baseline. Отчёт проверяется по схеме,
смысловым инвариантам, профилю и дереву A; это не цифровая подпись артефакта.

Репозиторий монтируется read-only, отчёты отдельно. При сканировании сеть
ограничена внутренней связью scanner/analyzer без интернета и опубликованных
портов. Подготовка зависимостей и образов выполняется отдельно и явно.
Non-root UID/GID оператора, read-only root FS, tmpfs, drop ALL capabilities и
no-new-privileges включены штатным launcher. Container logs отключены. Перед
стартом проверяются immutable image reference/platform IDs. SHA-256 пакета/lock
не подтверждает издателя: доставка и происхождение доверенные. Docker daemon и
host operator входят в trust boundary; SIGKILL/daemon loss требует ручного
[cleanup точного проекта](docs/admin/operations.md). Копии private reports в Jenkins/
backup требуют отдельно настроенных владельцем RBAC/retention.

## Чувствительные артефакты

По требованию владельца `report.json` и `report.html` содержат значения и
контекст ПОЛНОСТЬЮ, включая находки в неполном отчёте. Артефакты Jenkins
должны иметь подходящие права доступа и сроки хранения. Не загружайте их
в публичные Issues, PR и внешние сервисы. В логах по умолчанию только сводка,
без найденных значений, исходных текстов и полных ответов Analyzer.

HTML экранирует значения и пути, использует только статические JS/CSS
с CSP hashes и не зависит от внешних ресурсов.
URL/фрагмент из репозитория не исполняется и не загружается автоматически.

Новые output-каталоги/файлы имеют 0700/0600, symlinks в output path запрещены.
Существующий конечный output обязан принадлежать UID оператора и не иметь
group/other permissions; публичный/чужой каталог отвергается без chmod/chown.
Атомарность относится к одному файлу, не к JSON/HTML вместе. Если исправление
артефакта после отказа записи невозможно, он может сохранить прежний статус;
код команды остаётся 2. Доверенный процесс не использует такой запуск как
baseline. [Точные границы](docs/cli-quickstart.md).

## Что означает результат

Поддерживаются только согласованные текстовые объекты и категории детекторов.
Чистый результат не подтверждает историю, содержимое LFS, подмодулей, архивов,
документов или изображений, а также абсолютную полноту обнаружения. `diff`
без совместимого baseline не подтверждает неизменённые файлы.
Ошибка или необработанный выбранный файл — код `2`, даже если находок нет.
Действительность credentials внешними запросами не проверяется.

[Независимый корпус кода](verification/stage-4/README.md) выявил пропуск
телефона, ошибки категорий/границ и дополнительные срабатывания текущей модели.
Техническое соответствие pipeline прямому Analyzer не устраняет этих ошибок.
Полный контекст находок хранится в памяти; bounded queue ограничивает число
текстов в обработке, не общий RAM. Timeout/отмена дожидаются локальной CPU-работы,
поэтому не являются жёстким ограничением времени процесса. [Границы API](docs/scan-api.md).
