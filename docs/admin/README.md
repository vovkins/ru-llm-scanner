# Руководство администратора

Администратор готовит доверенное локальное окружение, передаёт его пользователю
и сопровождает образы, конфигурацию и артефакты. Пользователь сканирует подготовленный
Git-клон по [своему руководству](../user/README.md). Внешние LLM/API при анализе
не используются; подготовка пакетов и модели отделена от offline runtime.

## Маршрут установки

| Что уже есть | Порядок действий |
| --- | --- |
| Доверенный готовый offline-пакет | [Импорт и установка](installation.md) → verify → контрольный scan → передача пользователю |
| Только исходники scanner и закреплённый upstream | [Fresh build](build.md) → проверка новых образов → export → установка/передача |
| Рабочая установка, нужен новый механизм | [Обновление и откат](updating-analyzer.md) с отдельными locks и проверками |
| Ошибка или прерванный запуск | [Эксплуатация и диагностика](operations.md) |
| Интеграция с Jenkins | [Доверенный pipeline](jenkins.md), после проверки отдельного запуска |

Ни опубликованного release, ни общедоступного registry-комплекта сейчас нет.
Готовый пакет передаёт ответственный за доверенную сборку; его происхождение
не подтверждается одним JSON или checksum-файлом.

## Среда и ответственность

Проверено на macOS Apple Silicon с Docker Desktop 29.6.1/Compose 5.2.0,
CPU Linux ARM64 внутри VM. Host tools проверялись на Python 3.12.14,
образы — на Python 3.11.16. [Матрица свидетельств](../../verification/README.md)
указывает границы. Настоящие Linux-host UID/ACL, AMD64, CUDA/GPU, другой
физический offline host, Jenkins controller и корпоративный PKI требуют проверки
в целевом окружении. Наличие upstream GPU Dockerfile не означает готовый GPU deployment.

Для штатного запуска нужны:

- Python **3.11+**, Docker Engine с platform inspect (API 1.49+) и Compose v2+;
- non-root оператор с доступом к daemon и к выбранному Docker context;
- заранее загруженные точные ARM64 images, соответствующие deployment lock;
- подготовленный self-contained клон, доверенные внешние config/baseline roots;
- Docker-доступ к bind-путям, место для image store, приватных отчётов и временных файлов.

Доступ к Docker является привилегированным доступом хоста. Не выдавайте его
произвольным разработчикам/недоверенным CI jobs. Scanner не защищает от владельца
хоста/daemon, не заменяет ACL и не определяет доверенное происхождение baseline.

Начальная проверенная VM имела **8 GiB RAM / 10 CPU**. Это характеристика стенда,
не минимальные системные требования. Веса NER занимают около 709 MB; полный
размер images, transfer tar, сохранённых contexts и отчётов больше. Планируйте
запас диска под старый и новый комплект и backups. Минимальную RAM, размер клона
и SLA для вашей нагрузки предстоит измерить; [runtime budgets](../reference/runtime.md)
ограничивают контейнеры, но не доказывают ёмкость.

Для fresh build дополнительно нужны Git, venv с dev/runtime dependencies,
BuildKit, локальный закреплённый base и разрешённые источники upstream, Python/OS
пакетов и модели. После сборки они не требуются пользователю для scan.

## Состав доверенного комплекта

| Компонент | Роль |
| --- | --- |
| `scripts/docker_scanner.py` | Stdlib host launcher; создаёт приватный Compose, управляет запуском и cleanup |
| Scanner image | Установленный CLI, schema/renderer, словарная политика/правила и engine locks |
| Analyzer image | Закреплённые распознаватели, NER-веса, runtime packages, словарь и notices |
| Source lock | Upstream SHA/export-list, модель, constraints, патчи и хеши; вход подготовки |
| Runtime lock | Измеренная идентичность конкретного Analyzer после seal; вход engine bundle |
| Deployment lock | Точные scanner/Analyzer reference и platform IDs, build inventory; вход runtime |
| Offline-пакет | `images.tar`, `deployment.json`, четыре engine assets, `checksums.json` |

Схема связи артефактов и правила доверия — в [справочнике](../reference/artifacts.md).
Lock из Git описывает измеренный прежний образ; fresh build получает собственный
runtime/deployment. Нельзя заменить ID ради успешного verify или полагаться на tag.

## Проверка установки и передача пользователю

1. Выполните [импорт или fresh build](installation.md) под оператором, который
   будет запускать scanner. Зафиксируйте версию launcher, выбранный deployment
   и происхождение images. Старый рабочий комплект сохраните.
2. Получите `verify` с кодом 0. Он проверяет IDs/платформу, но не ready модели.
3. Выполните контрольный snapshot синтетического локального клона по
   [процедуре установки](installation.md#контрольный-snapshot). Сопоставьте
   итоговый код, private reports и неизменность входа; исследуйте код 2.
4. Передайте пользователю каталог установки, явный путь lock, клон/ref,
   private output parent, при необходимости approved config/baseline roots
   и [руководство пользователя](../user/README.md).
5. Определите владельца baseline, правила продвижения только после exit 0,
   хранение цепочки и доступ к отчётам/архивам/backups. Любой clean-файл без
   доверенного завершённого запуска недостаточен.
6. Назначьте CPU/RAM/timeouts/concurrency под целевую нагрузку, retention и
   ответственного за диагностику. Зафиксируйте непроверенные особенности среды.

Подготовка SCM, сеть организации, jobs/credentials/RBAC и публикация пакетов —
ответственность владельца инфраструктуры. Инструкции и пример Jenkins сами по
себе эти настройки не применяют. Перед распространением также решаются
[лицензия и состав notices](../licensing.md).

## Повседневное сопровождение

Пользовательский scan не должен менять входной клон, выполнять pull/build или
отправлять тексты наружу. Отчёты полные: ограничьте owner/access, выдачу HTML,
CI artifacts, transport и backups. `0700`/`0600` на локальной FS не определяют
права доступа в Jenkins или хранилище организации.

Обычные ошибки/сигналы очищают только ресурсы собственного запуска; SIGKILL/потеря
daemon могут оставить их. [Cleanup](operations.md#потерянный-запуск) использует
точный project label и проверку владельца, без broad prune/остановки других проектов.
После нового Analyzer/словаря/профиля нужен новый snapshot; старые артефакты и
точный прежний deployment сохраняются для [отката](updating-analyzer.md).
