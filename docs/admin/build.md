# Сборка и обновление локальной установки

Это основной маршрут **текущих исходников**; в опубликованном v0.2.0 новых команд
нет. [Предпосылки и ресурсы](README.md) готовит администратор. Сборка выполняется
на сервере с интернетом, под non-root оператором с доступом к rootful Docker.

## Первая сборка

В доверенном checkout scanner:

<!-- walkthrough:build -->
```sh
make build
make test
```
<!-- /walkthrough:build -->

`build` сам создаёт закреплённое Python-окружение, получает точные upstream
исходники, зависимости и модель, собирает Analyzer и Scanner, проверяет их
идентичность и выполняет короткий synthetic scan. Он также готовит unit assets
для `test`. Указывать wheel, hashes, промежуточные пути и редактировать JSON не нужно.
`test` выполняет [шесть групп](../reference/everyday-tests.md) без скрытых загрузок.

После успешного завершения:

```sh
make scan REPO='/srv/git/example project'
```

Путь заменяется локальным self-contained клоном. Новый snapshot не строит и не
скачивает образы. Не вызывайте make входного проекта: рабочий каталог — scanner.

## Повторный build и обновление

`make build` проверяет кеш и переиспользует соответствующие образы. Повреждённые
bytes не принимаются. При missing/corrupt test assets или cached Python environment
явный `make build` готовит новую проверенную копию; `make test` сам не ремонтирует
и возвращает 2. Старые каталоги автоматически не удаляются.

Для обновления выберите проверенную версию исходников scanner обычным доверенным
SCM-процессом, затем снова выполните `make build` и `make test`. Сам build не
переключает Git-ветку и не выбирает proxy main/latest. Влияющие inputs проверяются
по содержимому; README входит в provenance пакета, поэтому его изменение также
требует build. Большинство остальных Markdown-страниц не входят в этот отпечаток.
Точный состав — внутренний контракт [workflow_state.materials](../../scripts/workflow_state.py).

Текущий комплект переключается **только после успешных проверок**. Неудачная
сборка оставляет предыдущий комплект и images. При новых несовместимых исходниках
scan откажет до успешного build; для возврата используйте прежний доверенный
checkout с его сохранённым состоянием и тем же daemon. Автоматического downgrade нет.
Старые reports и baseline сохраняйте. После смены engine/profile создайте новый
полный clean snapshot: старый baseline может оказаться несовместим.

Для проверяемого отката сохраняйте две отдельные доверенные установки: прежнюю
со своей `.build` и новую со своей `.build`. Новую сначала подготовьте обычными
`make build` и `make test`; затем выбирайте её каталог для команд пользователя
или `SCANNER_HOME` агента. Возврат означает выбор прежнего готового каталога на
том же daemon. Не копируйте JSON, не меняйте image IDs и не переименовывайте
образы между установками. Старый clean baseline подходит только точным прежним
engine/profile и состоянию A; новая версия требует нового полного snapshot A.
После0 можно отдельно одобрить baseline, после1/2 — нельзя. Это тот же процесс
сборки на сервере с интернетом; отдельного набора offline make-команд нет.

## Что хранится автоматически

`.build/workflow` содержит private окружения, build-каталоги и выбор проверенного
комплекта для daemon/platform. `.build/artifact-cache` — проверяемый hash-cache.
Это внутренние файлы инструмента, а не конфигурация оператора. Не переносите один
JSON между установками и не подставляйте Image IDs для обхода проверки.

Параллельные builds на одном daemon сериализуются; текущий scan продолжает
использовать уже выбранный комплект. Смена Docker context требует успешной сборки
для выбранного daemon. Доверенный Docker endpoint и bind-пути задаёт оператор.

## Если сборка не прошла

Консоль показывает стадию, безопасный код и путь приватной диагностики. Проверьте
доступ к источникам, свободный диск, Docker/Compose, Python venv, владельца своих
каталогов. После исправления повторите `make build`; хеши и locks вручную не правьте.
Не публикуйте raw build logs, env, cache или отчёты в Issue/artifacts.
[Таблица ошибок и cleanup](operations.md).

Ручная CPU-сборка, полный release gate, export/import и старые релизные архивы —
[расширенный маршрут](advanced.md), который не нужен для обычного первого запуска.
