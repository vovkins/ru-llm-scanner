# Baseline: подтверждение неизменённых файлов

Baseline — доверенный предыдущий JSON-отчёт для A. Это не список секретов
для игнорирования. Задача — перенести подтверждение неизменённых файлов,
когда весь B повторно не анализируется.

## Допуск

Допустимый baseline обязан иметь:

- `artifact_kind=scan_report` и поддерживаемую точную `schema_version`;
- `result.status=clean`, `exit_code=0`, пустые находки/ошибки;
- `coverage.complete=true`, `assurance=snapshot_verified` или `baseline_verified`;
- target commit равный A и target tree равный реально прочитанному дереву A;
- полный манифест A без `unverified`/`error` и корректный `manifest_sha256`;
- точное совпадение `profile_sha256` с текущим профилем;
- доверенное происхождение: артефакт сохранён защищённым процессом CI/оператором.

`contract_example` из примеров документации всегда отклоняется как реальный
baseline, независимо от иллюстрируемого результата. Валидация JSON Schema
не подтверждает качество анализа, подлинность файла или его пригодность.

Все записи A сверяются с деревом Git: сырой путь, mode и object OID;
повторы, пропущенные/добавленные пути и неправильные ссылки недопустимы.
`manifest_sha256` вычисляется из канонического JSON списка в порядке сырых
путей, с элементами `{path_bytes_b64,mode,object_oid,status,reason,encoding}`.
Это контроль целостности структуры, не цифровая подпись отчёта.

## Перенос A → B

1. Проверить схему, успешность, полноту, дерево A и профиль baseline.
2. Получить полный манифест B и сравнить его с A.
3. Неизменённые поддерживаемые записи с прежним `analyzed`/`inherited`
   получают `inherited`, сохраняя encoding и `evidence_report_id` предыдущего
   отчёта. Изменённый путь/mode/OID требует нового анализа.
4. Исключения/неподдерживаемые записи B классифицировать по текущей той же
   политике. Их содержимое не становится проверенным через наследование.
5. Проанализировать выбранные файлы B целиком, включая новые пути переименований.
6. Выдать полный манифест B. При успешной обработке assurance
   `baseline_verified`; при находках код `1`, такой отчёт новым baseline не служит.

Ссылка на непосредственно предыдущий отчёт вместе с полным манифестом B
позволяет продолжать цепочку без повторного чтения всей истории отчётов.
Доверенный CI хранит цепочку и артефакты по своей политике. Scanner не делает
запросов к Jenkins, GitHub или сети для их поиска.

## Таблица решений

| Вход | Статус baseline | Итог |
| --- | --- | --- |
| `snapshot` | `not_applicable` | Полный скан; baseline-аргументы недопустимы |
| `diff` без baseline | `not_requested` | Только изменённые файлы, `changed_files_only` |
| `--require-baseline` без файла | `missing` | `baseline_required`, код `2` |
| Совместимый доверенный отчёт A | `verified` | Возможен `baseline_verified` для B |
| Другая модель/образ/правило/словарь/score | `incompatible` | Код `2`, нужен snapshot |
| Изменён include/exclude/encoding/size/policy | `incompatible` | Код `2`, нужен snapshot |
| Другая версия алгоритма `scanner_semantics` | `incompatible` | Код `2`, нужен snapshot |
| Изменён только контекст, output, timeout, concurrency | Профиль не меняется | Прежний baseline допустим при остальных проверках |
| Отчёт с находками, ошибками, неполнотой, иным A | `invalid` | Код `2`; не скрывать fallback |
| Поддельная структура/неверный manifest, пример документации | `invalid` | Код `2` |

Предъявленный неподходящий baseline отклоняется даже без `--require-baseline`.
Если пользователь действительно хочет проверить только изменённые файлы,
он запускает diff без baseline явно.

## Новая модель и границы утверждения

Смена профиля требует полного snapshot **нового проверяемого состояния**.
Проверка изменённых файлов новой моделью не проверит ранее пропущенные
сведения в неизменённых файлах. Совместимость основана на полном fingerprint
из [конфигурации](configuration.md), а не только совпадении имени модели.

Чистый snapshot подтверждает поддерживаемую текстовую область B. Чистый diff
с baseline подтверждает ту же область условно на доверенном отчёте A.
Обычный diff подтверждает только проверенные изменённые файлы. Ни один режим
не утверждает отсутствие секретов в истории, неподдерживаемых объектах или
абсолютную полноту детекторов. [Состояния результата](reports.md).
