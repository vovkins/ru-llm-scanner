# CLI и конфигурация

Это спецификация; исполняемой команды пока нет. Основной запуск первой версии
будет из Docker. Git-входы читаются из локальных объектов, сеть не используется.
Scope/encoding правила реализованы как `TextPolicy` в
[Git API](git-reader.md); загрузчик полного JSON-профиля и scan pipeline
будут подключены на следующих этапах.

## Команды

```text
ru-llm-scanner snapshot --repo PATH --commit REV --output DIR [OPTIONS]
ru-llm-scanner diff --repo PATH --from REV --to REV --output DIR [OPTIONS]
```

`--repo`, `--output` и соответствующие ревизии обязательны и задаются только
через CLI. `--commit` несовместим с `diff`; `--from`, `--to`, `--baseline` и
`--require-baseline` несовместимы с `snapshot`. Пустые значения запрещены.
`--require-baseline` требует `--baseline`; при его отсутствии — код `2`.
Явно переданный, но неподходящий baseline всегда даёт `2`, без скрытого fallback.

| Аргумент | Значение по умолчанию | Смысл |
| --- | --- | --- |
| `--config FILE` | Нет | Явный доверенный JSON конфигурации v1 |
| `--baseline FILE` | Нет | Предыдущий отчёт для A |
| `--require-baseline` | `false` | Строгий diff с подтверждённым A |
| `--include GLOB` | `["**"]` | Повторяемые включающие шаблоны |
| `--exclude GLOB` | `[]` | Повторяемые исключения |
| `--encoding GLOB=NAME` | `[]` | Явная кодировка пути, например `legacy/**=cp1251` |
| `--max-file-bytes N` | `10485760` | 10 MiB до декодирования; превышение — ошибка |
| `--score-threshold FLOAT` | `0.35` | Порог Analyzer, диапазон `[0,1]` |
| `--context-lines N` | `2` | Число соседних строк, целое `0..100` |
| `--analyzer-url URL` | `http://analyzer:5001` | Внутренний адрес без credentials/query/fragment |
| `--connect-timeout-seconds N` | `5` | Подключение, положительное число |
| `--analyze-timeout-seconds N` | `600` | Один анализ полного файла, положительное число |
| `--ready-timeout-seconds N` | `120` | Ожидание готовности, положительное число |
| `--concurrency N` | `1` | Ограниченное число запросов, целое `1..16` |
| `--help`, `--version` | — | Локальная информация без анализа и обращений к сети |

10 MiB — начальный защитный предел объёма одного файла, не заявленная
производительность модели. 600 секунд допускают долгий CPU-анализ; это предел
ожидания, не SLA. Одна параллельная задача соответствует базовому CPU-профилю.
Точные эксплуатационные ориентиры проверяются на этапах 4 и 6. Автоповторов
анализа нет: повторный запуск явный. Ограничения никогда не дают «чистый» пропуск.

## Профиль v1

Формат — JSON, не YAML. Неизвестный ключ, повторяющийся JSON-ключ, неверный тип
и противоречивая комбинация — `config_error`. Файл конфигурации не ищется
автоматически в проверяемом проекте. Переменные окружения не переопределяют
настройки scanner; Docker-настройки сборки/Analyzer описываются отдельно.

```json
{
  "config_version": "1.0.0",
  "analysis": {
    "language": "ru",
    "score_threshold": 0.35,
    "entities": null,
    "dictionary_enabled": true
  },
  "scope": {
    "policy_version": "text-v1",
    "include": ["**"],
    "exclude": [],
    "encoding_overrides": [],
    "max_file_bytes": 10485760
  },
  "execution": {
    "analyzer_url": "http://analyzer:5001",
    "connect_timeout_seconds": 5,
    "analyze_timeout_seconds": 600,
    "ready_timeout_seconds": 120,
    "concurrency": 1
  },
  "presentation": {"context_lines": 2}
}
```

Приоритет: явно заданный CLI → соответствующее поле JSON → значения по
умолчанию. Повторяемый CLI-параметр заменяет весь список из JSON. Списки
include/exclude и кодировок в эффективной конфигурации сортируются и
дедуплицируются. Все эффективные поля сохраняются в отчёте.

`language=ru`, `entities=null` (все типы), `dictionary_enabled=true` —
обязательные значения первой версии для эквивалентного полного набора данных
прокси; выбор подмножества категорий и отключение словаря не входят в CLI v1.
Изменение score или настроек Analyzer допустимо только явно, с новым профилем
и новым полным snapshot. Встроенные уточнения/пороги распознавателей остаются
частью закреплённого upstream. Списка разрешённых значений в scanner v1 нет;
штатные upstream-фильтры заполнителей сохраняются.

## Правила путей и кодировок

Пути относительные к корню Git-дерева, разделитель `/`, регистр значим.
`*`/`?` действуют внутри сегмента, `**` — ноль или более сегментов;
символьные классы и отрицательные шаблоны `!` в v1 не поддерживаются.
Абсолютные пути, пустые сегменты и `..` в шаблонах запрещены.
Точка не имеет особого статуса: `**` включает dotfiles. Файл выбран при
совпадении хотя бы одного include и отсутствии совпадений exclude.
Шаблоны сопоставляются с UTF-8/backslashreplace-представлением сырого пути;
поэтому охват для путей с не-UTF-8 байтами обязательно показывается в отчёте.
Это правило входит в версию `text-v1`.

`encoding_overrides` — список объектов `{"pattern":"legacy/**","encoding":"cp1251"}`.
Назначение явно заменяет автоматический выбор кодировки, но обязано
согласоваться с BOM, если он есть. Совпадение нескольких правил с разными
кодировками — `encoding_conflict`, не выбор по порядку. Неизвестная кодировка
отклоняется до обработки. Никаких эвристических fallback в Windows-1251 для
всех файлов: почти любые байты иначе можно было бы выдать за текст.

## Подпись проверки

`profile_sha256` — SHA-256 UTF-8 канонического JSON объекта с ключами
`scanner_semantics`, `engine`, `analysis`, `scope`. Сериализация: сортировка
ключей, `ensure_ascii=true`, разделители `,` и `:`, без пробелов/перевода строки;
числовые параметры в этом объекте нормализуются к целым для целых полей,
score — к строке десятичного значения без лишних нулей (например `"0.35"`).
`engine` включает upstream SHA, digest образа, Analyzer signature, модель и
контрольную сумму весов, patchset/dictionary SHA-256. Различия CPU/GPU отражаются
через Analyzer signature и образ. Никакие пути локального клона не входят.

Правила декодирования, координат, путей, классификации, слияния результатов
и наследования имеют `scanner_semantics=scanner-v1`. Их изменение меняет эту
версию. `execution`, `presentation`, output и идентификатор запуска не входят
в профиль: они не должны менять успешно завершённый анализ. Timeout/сбой
вместо изменения результата дают неполную проверку. Версии scanner и среды
всё равно сохраняются для воспроизводимости.

## Артефакты и ошибки

`--output` — новая или пустая папка; непустая папка отклоняется, чтобы не
затереть прежние результаты. Планируемые файлы: `report.json`, `report.html`.
При возможности сохраняется также отчёт об ошибке; запись атомарная.
Ошибка записи отчёта/невалидные аргументы дают код `2` даже если файл отчёта
сохранить нельзя. Папка отчётов должна находиться вне read-only входного mount.

Типовые ошибки: `invalid_arguments`, `config_error`, `revision_unavailable`,
`git_object_missing`, `decode_error`, `file_too_large`, `analyzer_unavailable`,
`analyzer_timeout`, `analyzer_contract_error`, `baseline_required`,
`baseline_invalid`, `baseline_incompatible`, `report_write_error`.
Сообщения содержат безопасные идентификаторы/пути, без найденных значений,
контекста и ответа HTTP целиком. [Итоги и структура](reports.md).

## Примеры проектируемого интерфейса

Команды ниже ещё не исполняются: runtime будет реализован в следующих этапах.

```bash
# Полный снимок; при чистом завершённом результате код 0.
ru-llm-scanner snapshot --repo /repo --commit HEAD --output /reports/initial

# Обычный diff: без baseline подтверждены только изменённые файлы.
ru-llm-scanner diff --repo /repo --from COMMIT_A --to COMMIT_B \
  --output /reports/changed

# Строгая проверка с предыдущим отчётом A.
ru-llm-scanner diff --repo /repo --from COMMIT_A --to COMMIT_B \
  --baseline /reports/initial/report.json --require-baseline \
  --output /reports/verified

# Ошибка: snapshot не принимает baseline; ожидается код 2.
ru-llm-scanner snapshot --repo /repo --commit HEAD \
  --baseline /reports/initial/report.json --output /reports/invalid
```

Недоступная ревизия означает `revision_unavailable`, не автоматический fetch.
Отчёт с другим профилем в строгом diff означает `baseline_incompatible`;
дальнейшее действие — новый snapshot, не подмена baseline. Чистый diff при
A=B без baseline даёт `changed_files_only`, даже если ни один файл не выбран.
