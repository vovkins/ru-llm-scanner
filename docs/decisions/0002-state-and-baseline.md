# ADR-0002: проверка состояний и baseline

Статус: принято 2026-10-18 в общем плане; спецификация — этап 1.

## Контекст

Первому аудиту нужен снимок, последующему CI — проверка нового состояния.
Распознавание зависит от соседнего контекста; проверка только добавленных
строк может потерять многострочные значения и смену смысла прежнего текста.

## Решение

`snapshot` проверяет текстовую область дерева коммита. `diff` сравнивает
точные A/B и анализирует полные изменённые файлы B. Совместимый доверенный
baseline распространяет подтверждение на неизменённые файлы. При изменении
профиля нужен полный snapshot. Обход истории не входит в первую версию.

## Последствия

Первый скан дороже последующих, а результаты имеют явный охват. Промежуточный
секрет может сохраниться в истории, даже если B чист. Проверка каждого коммита
требует запуска CI для каждого состояния. Baseline — доверенный артефакт,
не allowlist и не криптографическое доказательство отсутствия секретов.
