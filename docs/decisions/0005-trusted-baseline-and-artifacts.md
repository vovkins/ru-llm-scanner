# ADR-0005: Доверенный baseline и атомарность отдельных артефактов

Статус: принято планом [этапа 5](https://github.com/vovkins/ru-llm-scanner/issues/9),
реализовано 2026-10-19.

## Решение

CLI получает доверенную engine-папку явно; default абсолютный и не зависит
от cwd/окружения репозитория. Runtime validator использует упакованную копию
публичной schema v1 и смысловые инварианты независимо от dev fixture checker.
Тест подтверждает тождество schema в пакете и `schemas/`.

Baseline — только чистый полный scan_report от доверенного процесса, прошедший
schema/semantic validation, проверку exact profile и всех raw path/mode/OID
по реальному дереву A. Контрольные суммы не являются цифровой подписью.
Неизменённые analyzed/inherited наследуются со ссылкой на непосредственно
предыдущий отчёт, без загрузки всей цепочки; unsupported переклассифицируются,
excluded определяются текущим scope. Любой отказ явный, без fallback.

Output резервируется как новая/пустая папка вне входа, через dirfd/NOFOLLOW
и эксклюзивный marker. Каждый файл публикуется атомарно из временного файла:
первое создание hard link не заменяет существующую запись, исправление
собственного артефакта использует replace после проверки inode. Права новых
каталогов/файлов — 0700/0600. Symlinks в output path отклоняются.

## Следствия и ограничения

JSON/HTML содержат одни данные и все чувствительные значения. HTML получает
только экранированный текст; JS/CSS статические и разрешены по CSP hash,
фильтры не используют innerHTML, внешняя сеть не нужна.

Двухфайловой транзакции нет. При сбое записи scanner возвращает 2 и пытается
пометить оба артефакта reporting error. Если файловая система не позволяет
исправление, ранее записанный файл может остаться с прежним итогом. Доверенный
процесс допускает baseline только после кода 0; наличие JSON недостаточно.
Защита от активной подмены файлов владельцем хостового процесса не заявлена.
Реализация output требует POSIX; Windows-native не проверен.
