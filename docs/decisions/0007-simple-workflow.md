# ADR-0007: простой интерфейс поверх существующего механизма

Статус: build/scan/diff реализованы на согласованном этапе
[#40](https://github.com/vovkins/ru-llm-scanner/issues/40) по спецификации
[#39](https://github.com/vovkins/ru-llm-scanner/issues/39). Suite test реализован по [#43](https://github.com/vovkins/ru-llm-scanner/issues/43). В опубликованном v0.2.0 новых команд нет.
Общий план — [#38](https://github.com/vovkins/ru-llm-scanner/issues/38).

## Контекст

Оператор имеет сервер сборки с доступом в интернет. Текущий путь требует вручную
соединять исходники, модель, два образа, engine и deployment. Эти проверки полезны,
но их ручная координация мешает получить первый отчёт. Изменение Git reader,
формата отчётов или распознавания не требуется для упрощения запуска.

## Решение

Четыре цели Makefile — build/scan/diff/test, help — справка. Единый stdlib host
CLI `./scanner` владеет логикой, make делегирует. Обычный scan сам владеет
контейнерным жизненным циклом. Jenkins получает точные коды прямого CLI.

Инструмент автоматически готовит окружение, определяет native Docker platform,
соединяет существующие prepare/build/seal/engine/deployment/verify и выбирает
только успешный локальный комплект. Состояние и кеш внутренние; ручной JSON не
нужен. Выбор атомарный, старые комплекты сохраняются при ошибке. Нет silent
fallback к legacy ARM64 lock, state входного репозитория или чужому daemon.

Сеть допустима при явной подготовке build. Scan использует готовые локальные
ресурсы с прежней изоляцией и приватностью; отдельная offline установка не
становится новым основным процессом. ADR-0006 продолжает задавать контейнерную
изоляцию/ownership/cleanup. Его прежний ручной выбор deployment скрывается новым
интерфейсом, а существующие низкоуровневые команды сохраняются.

## Последствия и проверка

Появляется одна обязанность сопровождения: проверить передачу параметров и
выбор фактического комплекта, не дублируя детекторы/Git/pipeline. Make и scan
имеют разные exit status, поэтому Jenkins использует прямой CLI. Появление
понятной оболочки не означает прохождения новой модели/платформы/релиза.

Единственный подробный контракт параметров, путей, ошибок и поведения —
[спецификация](../reference/simple-workflow.md). Матрица будущих испытаний и
карта переиспользования — [протокол этапа](../../verification/simple-workflow-stage-1/README.md).
Публичные интерфейсы proxy и перенос новой Base64-политики относятся к этапам5–6.

Пошаговая документация текущего интерфейса: [admin](../admin/README.md), [user](../user/README.md). Ручной explicit путь и v0.2.0 вынесены в [расширенный раздел](../admin/advanced.md). Автоматизация proxy update и новый Jenkins pilot завершены на этапах5–6 #38 и поставляются в v0.3.0.
