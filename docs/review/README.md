## Вывод

Основные слои разделены: Git/text → pipeline → Analyzer/словарь → findings/report;
подготовка upstream и запуск готовых образов имеют разные входы и обязанности.
В проверенных путях snapshot/diff и baseline не найден подтверждённый сценарий
ложного clean. Это вывод статического ревью с указанными ниже границами,
а не гарантия отсутствия дефектов или полноты распознавания.

Подтверждены **три дефекта**: P1 в Jenkins adapter, P2 в чтении deployment JSON
и P2 в legacy dev-образе. Дополнительно зафиксированы два предложения по
усилению защиты и сопровождению, пробелы документации и известные ограничения.
**До итоговой приёмки необходимо устранить P1 и восстановить применимые проверки.**
Продуктовые исправления относятся к отдельно согласуемому этапу 2.
[Подробный план исправлений #18](https://github.com/vovkins/ru-llm-scanner/issues/18)

## Что выполнено заново

- Статическое ревью собственного runtime, схемы, build/launcher/transfer,
  интеграции upstream, Jenkins example и существенных путей test harness.
- Пять subprocess случаев Jenkins на синтетическом launcher: четыре невалидных
  ответа дали ошибочный 0; корректный error-summary с кодом 2 дал 2.
- Проверка поведения writer/launcher на собственной пустой папке 0777;
  опубликованные файлы сохранили 0600. Доступ к их значениям другим пользователем
  не проверялся; существующая политика CLI описана в quickstart.
- FIFO preflight: собственный subprocess пришлось завершить внешним таймаутом
  2 секунды, Docker не вызывался. Это некорректный ввод оператора,
  не исполнение кода сканируемого репозитория.
- В готовом legacy scan-test image без сети текущий pipeline завершил импорт
  отсутствием jsonschema; root image ID сохранён в completion.json.
- 13 существующих unit tests Jenkins/output/launcher прошли без skipped.
  Они не покрывали RV-01/RV-02, что показали отдельные наблюдения.
- Независимый расчёт строк/столбцов подтвердил 4200 позиций на 200 текстах
  с CR/LF/CRLF и emoji, seed 1701.

Новые прогоны реального NER, всего upstream subset, production acceptance,
upgrade/rollback, нагрузочные и браузерные проверки здесь не заявляются.
Предыдущие свидетельства остаются в [main integration](../../verification/main-integration/README.md)
и [этапе 7](../../verification/stage-7/README.md). Комплексный повтор после
исправлений и прохождение новых инструкций запланированы на этап 4 нового цикла.

## Воспроизведение

Нужны dev dependencies проекта, POSIX и Python 3.11+. Из корня checkout:

```bash
.venv/bin/python docs/review/reproduce.py --output .build/review-observations.json
```

Скрипт создаёт собственные синтетические каталоги, fake launcher и FIFO,
удаляет их, не вызывает Docker/сеть и не меняет продуктовый код. Вывод —
наблюдения, **код 0 этого диагностического скрипта не означает исправность продукта**.
Сравнивайте recorded hashes и результаты с проверяемой ревизией. Публичный JSON
не содержит текстов репозитория или полных report.json/report.html.

## Границы заключения

Это внутреннее ревью, не независимая сертификация и не полный аудит внешних
зависимостей/весов. Метрики frozen code-v1 остаются TP 33 / FP 13 / FN 4;
46/46 parity не исправляет модельные пропуски. Модель/правила/разметка не менялись.
Очередь не ограничивает всю память, CPU join не жёсткий deadline, JSON/HTML
атомарны отдельно. Host/daemon, происхождение baseline/locks/образов доверенные.
Другие платформы, реальный Jenkins и новая vulnerability database не проверялись.

Релиз, теги, registry, новые merge, лицензия и внешние настройки не изменялись.
Отчёт подготовлен отдельно от исправлений; подробный план следующего этапа
показывается пользователю для отдельного согласования.
