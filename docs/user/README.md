# Сканирование локального репозитория

Работайте из доверенного checkout **ru-llm-scanner**. Администратор один раз
выполняет [make build и make test](../admin/build.md) той же учётной записью
на том же Docker daemon. Для scan не нужны ручные locks, установка venv или
запуск постоянных сервисов. Входной проект уже склонирован отдельно.
В опубликованном v0.2.0 используется [прежний explicit launcher](../admin/explicit-launcher.md).

## Первый отчёт

Замените путь на свой локальный клон. Пробелы и Unicode допустимы; кавычки обязательны.
Команды ниже выполняются в одной POSIX shell-сессии из checkout scanner:

<!-- walkthrough:head -->
```sh
REPO="$HOME/git/пример project"
make scan REPO="$REPO"
```
<!-- /walkthrough:head -->

Проверяется **HEAD**, а в консоли появляются абсолютные пути `report.json` и
`report.html`. Откройте напечатанный HTML локально в браузере; сервер и интернет
не нужны. Наличие находок означает scanner 1, поэтому make обычно завершится 2.
Это ожидаемый результат; точные коды для CI описаны ниже.

Вход — self-contained обычный или bare Git-клон со всеми нужными commit/tree/blob.
Linked worktree, alternates и внешняя Git metadata не поддерживаются.
[Точные требования к клону](../git-reader.md).
Читаются **tracked Git-объекты коммита**, а не файлы рабочей папки. Staged,
untracked и незакоммиченные изменения не входят в результат. Scanner не делает
checkout/fetch, не запускает код, hooks, filters, Makefile и `.env` входного проекта.
Не меняйте object store параллельно с анализом.

## Конкретный коммит и каталог

Для повторяемого запуска используйте полный SHA. Например, задайте `B` своим
коммитом; `HEAD` ниже — рабочее начальное значение:

<!-- walkthrough:commit -->
```sh
B=HEAD
make scan REPO="$REPO" COMMIT="$B"
```
<!-- /walkthrough:commit -->

Default root — `${XDG_STATE_HOME:-$HOME/.local/state}/ru-llm-scanner/reports`.
Каждый запуск создаёт уникальный подкаталог с UTC-временем и случайным ID.
Каталоги имеют `0700`, JSON/HTML — `0600`. Если задан `XDG_STATE_HOME`, он должен
быть абсолютным и вне клона. Путь без прав, symlink или пересечение с input
дают ошибку; автоматического fallback в cwd/временный каталог нет.

Необязательный `OUTPUT` выбирает **новый либо пустой приватный** каталог вне
клона с уже существующим parent. Пример для отдельной свежей папки:

<!-- walkthrough:output -->
```sh
umask 077
RESULTS="$HOME/scanner results"
mkdir -m 700 "$RESULTS"
make scan REPO="$REPO" COMMIT="$B" OUTPUT="$RESULTS/snapshot-B"
```
<!-- /walkthrough:output -->

Этот `mkdir` предполагает, что parent HOME существует, а RESULTS ещё нет.
При повторе выберите другое имя. Непустой output не перезаписывается, публичные
или чужие права не исправляются автоматически. Отчёты содержат **полные значения**
и контекст: ограничьте выдачу, backups и срок хранения. Пути и техническая
сводка выводятся в console; найденные значения туда не печатаются.

## Как читать результат

| Прямой `./scanner scan` или `diff` | Действие |
| --- | --- |
| `0` | Проверка завершена без находок; оцените coverage/assurance |
| `1` | Разберите все находки в отчёте |
| `2` | Ошибка или неполнота; исправьте причину и повторите в новый output |

GNU Make возвращает собственный код ошибки рецепта, обычно **2 и при scanner 1**.
Консоль показывает настоящий результат scanner. Для точных кодов используйте:

<!-- walkthrough:direct -->
```sh
./scanner scan --repo "$REPO" --commit "$B"
```
<!-- /walkthrough:direct -->

При `set -e` ненулевой код обрабатывайте явно. Автоматизация использует process
code и JSON; человеческую консоль нового CLI парсить не следует.
При раннем отказе отчётов может не быть. Найденные значения при коде 2 остаются
важными, но отсутствие находок не превращает неполную проверку в clean.

HTML содержит поиск, фильтры и группировку, полное значение/контекст и координаты
с 1; конец диапазона исключающий. Confidence — score распознавателя, не
вероятность действительности секрета. Внешняя действительность токенов не проверяется.
[Формат JSON/HTML](../reference/reports.md).
[Синтетический HTML](../../examples/demo/report.html) и
[JSON](../../examples/demo/report.json) иллюстрируют формат, **не подходят как baseline**.

| Статус файла | Значение |
| --- | --- |
| `analyzed` | Полный текст обработан сейчас |
| `inherited` | Подтверждение перенесено из совместимого baseline |
| `unverified` | Неизменённый файл обычного diff не проверен |
| `excluded` | Вне явного include/exclude |
| `unsupported` | Вне поддерживаемой текстовой области |
| `error` | Обязательная обработка не завершена |

`coverage.complete=true` относится к **заданной** проверке; diff может содержать
`unverified`. Смотрите `result.assurance`: `changed_files_only`, `snapshot_verified`
или `baseline_verified`. Эти значения описывают область обработки, не полноту
самих детекторов. [Режимы/охват](../reference/scan-modes.md),
[каталог и известные FP/FN](../reference/detection.md).

## Переход A → B

Задайте `A` и `B` коммитами своего проекта. Для истории из двух и более коммитов
следующий пример сравнивает HEAD~1 с HEAD:

<!-- walkthrough:diff -->
```sh
A=HEAD~1
B=HEAD
make diff REPO="$REPO" FROM="$A" TO="$B"
```
<!-- /walkthrough:diff -->

Сравниваются конечные состояния напрямую, без merge-base. Проверяется **полный
файл B**, включая неизменённые строки новых, изменённых и переименованных файлов.
Обычный diff имеет `assurance=changed_files_only`; неизменённые файлы не подтверждены.
При A=B без baseline проверено только отсутствие изменений.

Для strict-перехода сначала нужен доверенный clean snapshot **A**:

<!-- walkthrough:baseline -->
```sh
./scanner scan --repo "$REPO" --commit "$A" --output "$RESULTS/snapshot-A"
```
<!-- /walkthrough:baseline -->

Продолжайте **только после кода 0**, завершённого запуска и сохранения обоих
артефактов. Затем передайте этот JSON явно:

<!-- walkthrough:strict -->
```sh
make diff REPO="$REPO" FROM="$A" TO="$B" \
  BASELINE="$RESULTS/snapshot-A/report.json" REQUIRE_BASELINE=1
```
<!-- /walkthrough:strict -->

Совместимый baseline подтверждает неизменённые файлы A в B; результат имеет
`assurance=baseline_verified`. Нужны тот же A/tree и полный профиль. Находки,
ошибки, чужой коммит, другая модель/образы/словарь/score/scope делают baseline
непригодным. Переданный неподходящий baseline даёт 2 даже без strict-флага;
отката к обычному diff нет. При смене engine/profile сделайте новый clean snapshot.

Происхождение baseline обеспечивает оператор: JSON не является подписью доверия.
Продвижение не автоматическое; только завершённый clean запуск с кодом 0 и
совместимостью может стать основанием следующего перехода. HTML/JSON атомарны
по отдельности, общей транзакции нет. [Полные правила](../reference/baseline.md).

Промежуточные коммиты не проверяются. Секрет, добавленный и удалённый между A/B,
может остаться в истории. Для разового аудита используйте snapshot; в CI проверяйте
каждый принятый переход. Содержимое LFS/подмодулей, Office/PDF/OCR, изображения,
архивы и незакоммиченные изменения вне обещанного охвата. SVG/XML — только текст.
Неподдерживаемые объекты и исключения видны в манифесте.

## Необязательная конфигурация

Без CONFIG действуют defaults. Сложный профиль передайте явно из доверенного
JSON вне клона; автоматического поиска конфигурации нет. За основу можно взять
[синтетический config с defaults](../../examples/config/scanner.json).

<!-- walkthrough:config -->
```sh
cp examples/config/scanner.json "$RESULTS/approved.json"
make scan REPO="$REPO" CONFIG="$RESULTS/approved.json"
```
<!-- /walkthrough:config -->

Пример использует ранее созданный RESULTS; при другом пути замените его своим. CLI flags доступны через `./scanner scan --help` и имеют
приоритет над JSON; повторяемый flag заменяет весь соответствующий список.
Include/exclude/encoding/size/score меняют профиль baseline; context и execution
budgets сами по себе профиль не меняют. `.gitignore` не исключает tracked файлы.
Слишком большой выбранный текст, decode error или timeout дают неполноту, а не clean.
[Конфигурация](../reference/configuration.md), [Make/CLI flags](../reference/simple-workflow.md).

## При ошибке

Нет установки/stale inputs — попросите администратора выполнить `make build`.
Нет объекта — подготовьте его доверенным SCM-процессом вне scanner. Непригодный
output — выберите новый приватный путь вне клона. Несовместимый baseline —
проверьте A/профиль и сделайте новый snapshot. При Analyzer/timeout проверьте
приватный отчёт и budgets с администратором. [Диагностика](../admin/operations.md).
Повторный запуск сам не делает fetch/build и не исправляет права чужих файлов.
