# Новая запись certifi и границы её применимости

Обнаружена при явном обновлении advisory-баз 2026-10-21 МСК (query UTC
2026-10-20T21:32). Это отдельная запись, не одно из четырёх ранее принятых
native-исключений. **2026-10-21 владелец явно выбрал сохранение версий с
ограничением HTTPS** в ответе в чате; решение зафиксировано в
[#34](https://github.com/vovkins/ru-llm-scanner/issues/34).
Предложенный patch не применён. Исправление certifi этим решением не заявляется.

## Факты

[GHSA-6q48-6c7w-9gw2](https://github.com/certifi/python-certifi/security/advisories/GHSA-6q48-6c7w-9gw2)
опубликована 20 октября. Речь о доверии emSign roots при компрометации ключей
промежуточных CA: on-path атакующий может подменить TLS-сеанс.
В Analyzer закреплён `certifi==2026.7.22`, в Scanner — `2026.10.18`.
Maintainer указывает удаление затронутых roots в 2026.10.18; OSV диапазон включает
и эту версию до fixed 2026.10.19. Поэтому две OSV записи не означают два доказанных
эксплуатируемых дефекта. [Версия 2026.10.19](https://github.com/certifi/python-certifi/releases/tag/2026.10.19)
доступна; вариант унификации обоих кандидатов на ней был подготовлен, но не выбран.

В штатном Docker scan Scanner обращается по HTTP к Analyzer в internal network;
HF/Transformers работают offline, model/dependencies находятся в image. В этом
маршруте внешнего TLS-сеанса нет. Распознавание не отправляет текст наружу.
Это не заявление о безопасности произвольного HTTPS endpoint в расширенном
raw CLI: такой режим использует другое сетевое окружение/CA policy.

## Принятое решение и ограничение HTTPS

Для обоих неопубликованных CPU-кандидатов AMD64/ARM64 сохранены
`certifi==2026.7.22` в Analyzer и `certifi==2026.10.18` в Scanner, все requirements
и artifact/source locks. Эксплуатация этих кандидатов ограничена штатным
offline Docker-маршрутом, описанным выше: внутренний HTTP Scanner → Analyzer,
без внешних TLS-соединений и скачиваний при анализе.

Произвольный HTTPS endpoint raw Python CLI **не входит в принятую конфигурацию**.
Перед таким использованием требуется отдельная оценка CA policy и зависимостей,
устранение применимого риска и проверка соединения в целевой среде. Нельзя
переносить заключение об offline scan на произвольный HTTPS или отключать
проверку TLS-сертификатов как обход. Дополнительный программный запрет HTTPS
в CLI не вводился: это эксплуатационное ограничение, а не новая проверка URL.

Это решение по конкретному advisory и выбранному окружению. Оно не объявляет
пакет исправленным и не распространяется автоматически на новые advisory,
внешние TLS-клиенты либо другое сетевое окружение. Прежнее решение о четырёх
native-рисках сохраняется отдельно. Опубликованный v0.1.0, его tags/assets/images
и прежние default deployments не изменены.

## Подготовленный, но не выбранный вариант изменения

Проверен официальный universal wheel 2026.10.19 (размер/SHA/metadata).
Приватный patch затрагивает только 4 requirements, 2 artifact locks и связанные
hashes в source lock. Две прежние записи certifi объединяются в одну с components
Analyzer/Scanner; остальные версии, модель, словарь и frozen corpus сохраняются.
Нужны новые сборки/проверки кандидатов и новый baseline; опубликованный v0.1.0,
прежние default locks/images и решение по четырём native-рискам не меняются.

После выбора сохранения версий этот patch остался неприменённым. Новые сборки
ради записи решения не выполнялись: код и pinned inputs не менялись;
применимость финальных native evidence сохранена.

Свежий Debian audit дал те же 139 potential matches, новых advisory IDs относительно
прошлого разбора не найдено. Архитектурное исключение aligned-new проверяется
отдельно по фактическому AMD64 ELF, а не переносится из ARM64 по названию пакета.
